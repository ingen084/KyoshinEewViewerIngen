# 通知・音声メッセージ設計ガイドライン

## 基本原則

**簡潔性の原則**: ユーザーに素早く正確に情報を伝えることを最優先とする。冗長な表現や不要な装飾語は避け、核心となる情報のみを含める。

**伝達効率の重視**: 緊急時に迅速な情報伝達が求められるため、理解しやすく記憶に残りやすい表現を使用する。

## 音声キャッシュ最適化設計

**目的**: 音声合成のキャッシュシステムを活用し、固定部分と可変部分を分離することで、音声生成の高速化と品質向上を図る。

**設計原則**:
- 固定される可能性の高い定型文は独立したパーツとして分離
- 可変データ（震度、地名、マグニチュード等）は別パーツとして配置
- パーツ間のウェイトによる間合い制御のため、句読点は除去

## 音声読み上げルール

1. **句読点の扱い**
   - 音声読み上げでは末尾の句点（。）を省略する
   - 中間の句点は自然な間合いのために使用可能

2. **助詞の使用**
   - 聞き取りやすさを向上させるため、適切な助詞を使用
   - 例：「震源テスト県」ではなく「震源はテスト県」または単に「テスト県」

3. **頻度による表現の使い分け**
   - **頻繁な事象**（新規発表・最終報）：簡潔な表現
   - **稀な事象**（取消）：丁寧で明確な表現「〜は取り消されました」

## 情報精度に応じた表現

1. **確定情報**: 具体的な数値や場所名をそのまま使用
2. **推定情報**: 適切な曖昧表現を使用
   - 揺れ検知では震度数値ではなく「弱い揺れ」「強い揺れ」等の表現
   - 正確でない情報には明確な表現を避ける

## 情報の優先順位

1. **最重要**: 事象の種別（緊急地震速報、揺れ検知等）
2. **重要**: 規模・強度（最大震度、揺れの強さ）
3. **補助**: 場所情報（震源地、検知地域）
4. **詳細**: その他の付加情報（マグニチュード、深さ等）

## 継続報の取り扱い

- **EEW**: 新規発表と最終報のみ音声読み上げを行う
- **継続報**: 通知表示は行うが音声読み上げは省略
- **取消**: 重要な情報のため必ず音声読み上げを行う

## テンプレート命名規則

- **機能別プレフィックス**: `Eew`、`ShakeDetected`、`Earthquake` 等
- **用途別サフィックス**: `NotificationMessage`（表示用）、`VoiceNotification`（音声用）

## 実装例

### EEW音声テンプレート
```
緊急地震速報。最大震度4。テスト県西部
緊急地震速報最終報。最大震度3。架空県南部
緊急地震速報は取り消されました
```

### 揺れ検知音声テンプレート
```
弱い揺れを検知しました
揺れを検知しました（Medium レベル）
強い揺れを検知しました
非常に強い揺れを検知しました
```

### 揺れ検知通知テンプレート
```
揺れ検知 弱い 関東地方
揺れ検知 普通 近畿地方
[リプレイ] 揺れ検知 強い 九州地方
```

## 音声分離テンプレート（キャッシュ最適化）

### 配列テンプレート設計
音声キャッシュシステムを活用するため、各音声テンプレートは`string[]`として実装され、MultipleActionで順次VoicevoxSpeechActionに変換される。

**命名規則**: `*VoiceNotificationParts`

**実装例**:
```csharp
// EEW音声分離テンプレート
public static readonly string[] EewVoiceNotificationParts = [
    "{{if IsReplay}}リプレイ中です{{end}}",
    "{{if IsCancelled}}緊急地震速報は取り消されました{{else}}緊急地震速報{{end}}",
    "{{if !IsCancelled}}最大{{IntensityLongName}}{{if IsIntensityOver}}以上{{end}}{{end}}",
    "{{if !IsCancelled && EpicenterPlaceName}}{{EpicenterPlaceName}}{{end}}"
];
```

### ワークフローでの使用方法
1. MultipleActionの`IsParallel`を`false`に設定（順次実行）
2. 配列の各要素をVoicevoxSpeechActionとして追加
3. 空文字列になるパーツは自動的にスキップされる
4. パーツ間にはシステムが自動的にウェイトを挿入

### 利点
- **高速化**: 固定部分の音声キャッシュ活用
- **品質向上**: 定型文の発音一貫性確保
- **柔軟性**: 条件分岐による動的コンテンツ生成
- **保守性**: パーツ単位での独立修正可能
