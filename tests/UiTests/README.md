# 外部通信を禁止したUIテスト

実際のAXAML画面をAvalonia Headlessで操作する、小規模な回帰テストです。対象は初期設定ウィザード、テーマ編集画面、緊急地震速報パネル、災危通報の詳細表示、設定画面からの自動更新です。コンストラクターを省略したりprivateフィールドを書き換えたりせず、通常のViewとViewModelを使用します。

自動更新のテストは、更新確認からLinux向けの自己更新処理 (展開・実行権限の付与・旧バージョンの終了を待って実行ファイルを置き換え、起動するスクリプト) までを実際に動かします。旧バージョンのプロセスには`sleep`を使い、アプリケーションの終了だけをテスト用の処理に差し替えます。実際の単一ファイル形式の実行ファイルでの更新は `tests/IntegrationTest` の結合テストで確認します。

## 実行

Linuxでは.NET 10 SDK、Python 3、iproute2、util-linuxが必要です。

```bash
bash tests/UiTests/run.sh
```

WindowsではWSLのLinux環境を利用します。WSL側にも.NET 10 SDKが必要です。

```powershell
pwsh tests/UiTests/run.ps1
# Linux側のdotnetを個別に指定する場合
pwsh tests/UiTests/run.ps1 -DotnetPath /path/to/dotnet
```

ビルド済みの同じソースを再検査する場合だけ、`--skip-build` / `-SkipBuild`を指定できます。通常の`dotnet test`を通信可能な環境で直接実行すると、隔離確認で失敗します。通信禁止の条件を満たさない場合にテストを黙ってスキップすることはありません。

## 通信禁止の仕組み

1. 依存取得とビルドは通常の工程で行い、テスト対象の実行は別のLinuxネットワーク名前空間で行います。ループバック以外のインターフェースが存在しないことと、起動元とは異なる名前空間であることをテスト側でも検査します。UIテストで設定を有効にしても外部へ接続できません。VSTestのプロセス間通信には同じ隔離環境内のループバックを使用します。
2. 専用のApplicationは共通スタイルと実際の画面だけを初期化します。本番のサービス登録・受信開始・Sentry初期化は呼びません。HOMEも実行ごとの一時プロファイルへ変更し、通常の設定・テーマを読み書きしません。
3. テスト用HTTPは`FixtureHttpHandler`へメソッド・URL・応答を登録します。登録回数を超えた要求や未登録の要求は記録して拒否します。応答はメモリ内で生成され、DNSやソケットは使用しません。
4. 全テストに`OfflineNetworkAttribute`を適用し、終了時に監査結果を検査します。.NETのHTTP要求とテスト用応答の使用数を照合し、直接作成したHttpClientによる未登録要求、DNS解決、IPソケット接続も検出します。アプリが例外を捕捉してもテストは失敗します。テストの前後に発生した要求もアセンブリ終了時に検査します。

名前解決は専用mount namespace内の設定でローカルファイルだけに限定し、ホストの名前解決デーモンへの委譲も避けます。名前空間の作成には通常は非特権user namespaceを使います。GitHubホスト等で制限される場合だけ、`sudo -n unshare --net --mount`へ切り替えます。どちらも利用できなければ、テストを起動せず失敗します。ホスト全体のファイアウォールや名前解決設定は変更しません。

本番の`common.props`ではEventSourceが無効なため、UIテスト側で`EventSourceSupport=true`を明示しています。監査イベントの無効化や、登録したHTTP要求の診断イベントが欠落した場合も成功扱いにはしません。

現在の監査対象は、テストプロセス内で動く.NETコードです。自動更新のテストが起動するシェルコマンド (`chmod`・`sleep`・置き換え用のスクリプト) は同じネットワーク名前空間で動き、通信を行いません。外部プログラムを起動する本体E2Eテスト、OSネイティブのタイトルバー・通知・実GPUの検査は今回の対象に含めません。将来.NETの子プロセスを追加する場合は、同じネットワーク隔離を継承させ、そのプロセスにも要求監査を追加します。

## 失敗することの検証

通常の成功ケースの後に、以下を各1プロセスで実行します。

- 未登録のテスト用HTTP要求を捕捉して処理する。
- 直接作成したHttpClientの要求失敗を捕捉する。
- DNS要求を実行する。
- IPソケット接続の失敗を捕捉する。

これらは専用の環境変数で有効になる失敗検査です。対象テストが「想定外の通信要求」で失敗し、TRXと監査JSONにも違反が残ることをランナーが確認します。単なるビルドエラーや起動失敗を成功として扱いません。試行先はlocalhostまたは応答を生成するfixtureであり、外部サーバーは使用しません。

結果は`tmp/ui-tests/<実行日時>-<PID>/`のTRXと`audit/network-audit.json`に残ります。CIはLinuxの1ジョブのみで、macOSジョブは追加しません。

## テストを追加するとき

- `tests/KyoshinEewViewer.UiTests`に`[AvaloniaFact]`を追加し、実際の画面と通常のViewModelを作成します。画面は必ずfinallyで閉じ、静的なテーマ選択等も復元してください。
- 実時間のタイマーやバックグラウンド処理を待つときは`Ui.WaitUntilAsync`を使います。UIスレッドのジョブとアニメーションを進めながら待ちます。
- HTTPが必要なサービスには`new HttpClient(new FixtureHttpHandler())`を渡し、必要な応答を事前登録します。HTTP以外の入力は保存済みデータ・模擬受信・固定時計に差し替えます。
- 通信設定をOFFにするだけで禁止を実現しないでください。サービスを追加して要求が漏れると、名前空間で外部接続が止まり、監査でテストが失敗します。
- 原版の観測結果を期待値に使う場合も、維持したい仕様かを確認します。調査時の不具合を正解として固定しないようにします。
